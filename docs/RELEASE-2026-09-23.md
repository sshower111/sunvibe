# September 23, 2026 — UI consistency and protected contact form

## Changes
- Shared heading scale and bakery-brown heading color, consistent page widths and spacing, stable header/logo, and stronger text contrast.
- Reusable primary, secondary and outline buttons; matching inputs, textarea and native dropdown styles with left-aligned placeholders and visible focus states.
- Menu cards align category, title, description and price/action rows; mobile list layout remains compact.
- Minimum 48px touch controls; consistent gallery dialogs, footer and contact form.
- Cloudflare Turnstile contact verification with progress, expiry handling, error messages and retry. Server verification checks token, action and allowed hostname before sending email.
- Nonce-based Content Security Policy, production HSTS, frame protection and other security headers.

## Production requirements
Set these Vercel variables for Production before deploying:
- NEXT_PUBLIC_TURNSTILE_SITE_KEY: public widget key; available at build time.
- TURNSTILE_SECRET_KEY: server-only secret; mark sensitive.
- TURNSTILE_ALLOWED_HOSTNAMES: sunvillebakerylv.com,www.sunvillebakerylv.com

Allow both production hostnames in the same Cloudflare widget, preferably in Managed mode. Retain localhost/127.0.0.1 entries for local development if needed. Do not publish secret values or commit local environment files. Keep the existing Resend, Stripe and Blob configuration intact. Changing the public site key requires rebuilding/redeploying.

## Validation
The production checkout compiled successfully and generated all 28 routes. Existing Next configuration skips type checking and linting; pre-existing Stripe version, Chatbase window typing and legacy admin errors remain documented limitations. Storefront browser checks covered four widths (320, 390, 768, 1440), matching heading colors, stable logo on scroll, card-row alignment, search/reset and keyboard focus restoration. CAPTCHA success/expiry/retry/error states were tested with mocked challenges; the owner confirmed a real local challenge succeeded in Firefox. No test messages were emailed.

This release preserves production-managed gallery loading, Vercel Blob uploads, admin behavior and lazy provider initialization. No database migration is required. Security-audit findings outside this release remain unresolved; this is not a claim of comprehensive remediation.

## Deployment and rollback
Deploy only after production CAPTCHA configuration is present. Verify /, /menu, /gallery and /contact return successfully; check CSP/HSTS, live gallery data and visible contact verification. Confirm missing/invalid CAPTCHA cannot send a message. Roll back by promoting the previous Vercel deployment or reverting this release commit; no stored customer/catalog data changes are included.
